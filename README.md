# Hopaoems Project – All‑in‑One Verification Flow

## Overview
This repository follows the **Hopaoems System** strict UI/UX rules.  Phase S2 focuses on **template‑only** work – no JavaScript preview logic is allowed inside Jinja templates.  All interactive behaviour must live in `src/static/js/ui.js` and be validated by `verify_javascript.py`.

## Quality Gate & Verification
This project implements a strict multi-layer quality gate system. Every change **must** pass the unified gate before being considered stable.

```bash
# Cross-platform / CI
make gate

# Windows Native
.\gate.bat

# Python direct
python -m hopaoems.contracts.run_gates
```

The gate covers:
1.  **Macro Existence**: Verifies core UI components (Shell, Form, Card).
2.  **Zero Visual Token**: Blocks raw `class="..."` in page templates.
3.  **No Forbidden JS API**: Blocks `innerHTML`, `eval`, etc.
4.  **i18n Key Parity**: Ensured `en`/`zh-TW`/`vi` translations are synchronized.
5.  **Smoke Tests**: Verifies core routes and Role-Based Access Control (RBAC).

All commands must exit with code `0`.  If any step fails, the console output will list the offending files and the exact rule that was broken.

## Adding new templates
1. Use the **Hopaoems System** macros (`L.ui_*`, `F.ui_*`, `C.ui_*`).
2. **Never** add `<script>` tags or DOM‑manipulating JavaScript inside the template.
3. If you need client‑side behaviour, add a hook class (e.g. `js‑navigate`) and implement the logic in `src/static/js/ui.js`.

## Quick reference for prohibited patterns (checked by `verify_no_template_level_preview_js.py`)
- `FileReader`
- `createElement(`
- `appendChild(`
- `querySelector(`
- `addEventListener(`
- Any `<script>` block inside `sample/form.html`
